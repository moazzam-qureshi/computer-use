### Task 1: Card-level search driver

**What:** New module `upwork/search_driver.py` that takes (query, filters, max_cards) and returns `list[CardResult]`. Pure capture; no DB writes yet.

**Files:**
- `upwork/search_driver.py` (new)
- `tests/unit/upwork/test_search_driver.py` (new) — parses cards from a saved UIA dump

**Logic:**
1. `build_search_url(query, filters)` from existing [upwork/search.py](../../upwork/search.py)
2. `substrate.act.navigate(url)`
3. Wait for results region to render (poll observe.tree for the result list anchor; max 10s)
4. Walk visible cards; for each, parse: title, snippet, budget chip, posted-time, posted_at, skills, country, payment_verified, job_url
5. Scroll/PageDown to load more cards until `max_cards` reached or no new cards appear
6. Return `list[CardResult]`

Reuse parsing patterns from [upwork/feed_cards.py](../../upwork/feed_cards.py) — cards on the search page have similar structure to feed cards.

**Acceptance test:**
- Unit: parse 3 cards from saved dump, verify all fields populated correctly
- Manual smoke (no automated assertion): run `uv run python -c "from upwork.search_driver import search; print(search('RAG engineer', {'payment_verified': '1'}, max_cards=5))"` and visually confirm output

**Commit:** `BA: card-level search driver (upwork/search_driver.py)`

- `upwork/search_driver.py` (extend with `search_and_ingest`)

**Logic:**

**Acceptance test:**

**Commit:** `BA: corpus ingestion with idempotency (storage/market_corpus.py)`

### Task 4: Pure-SQL analytical layer

**What:** `ai/market_analysis.py` with deterministic aggregation functions. Tool `analyze_corpus` exposing them. Plus `backtest_setup` tool reusing `domain.scoring`.

**Files:**
- `ai/market_analysis.py` (new) — `skill_frequency`, `budget_percentiles`, `weekly_volume`, `country_breakdown`, `payment_verified_share`
- `assistant/ba_tools.py` (extend) — `analyze_corpus`, `backtest_setup` tools
- `tests/unit/ai/test_market_analysis.py` (new) — synthetic corpus fixtures, known outputs
- `tests/unit/ai/test_backtest.py` (new) — known patch + corpus → known count

**Logic for `analyze_corpus(window_days=30, source_pattern=None)`:**
- Single SQL pass building a temp set: `SELECT * FROM jobs WHERE scraped_first_at >= now() - <window> AND (source_pattern IS NULL OR source LIKE source_pattern)`
- Run each aggregator over the set in-process (Python, not SQL — corpus is small)
- Returns shape from spec §5.1

**Logic for `backtest_setup(filter_patch, window_days=30)`:**
- Convert `filter_patch` to `filter_dsl` via existing `_patch_to_filter_rules`
- Build a synthetic `Setup` with that `filter_dsl` (don't write to DB)
- Iterate corpus window, run `domain.scoring.score_job_against_setup` for each
- Return `{match_count, total, sample}` where sample is first 5 matches

**Acceptance test:**
- Unit: synthetic corpus with known skill/budget/country distribution → aggregators match expected values
- Unit: backtest with `min_hourly=80` against corpus seeded with mix of $50-$120 jobs → exact match count

**Commit:** `BA: analyze_corpus + backtest_setup tools (pure SQL, no LLM)`

### Task 6: Portfolio gap finder

**What:** `find_portfolio_gaps` tool. Mostly SQL clustering + 1 LLM call to score gap severity.

**Files:**
- `ai/agents/ba_proposer.py` (new) — `rank_gap_severity` LLM helper
- `ai/prompts/ba_gap_severity.py` (new) — prompt string
- `assistant/ba_tools.py` (extend) — `find_portfolio_gaps` tool
- `tests/integration/ai/test_portfolio_gaps.py` (new)

**Logic:**
1. Pull corpus over `window_days` via `analyze_corpus`
2. Cluster jobs by overlapping skill tokens (simple set intersection, top-N skills per cluster)
3. For each cluster, compute `portfolio_coverage_score`: count portfolio items whose `relevance_tags` intersect the cluster's skill set / total portfolio items. Deterministic.
4. Call `rank_gap_severity` (LLM) with `{cluster_name, sample_jobs, demand_count, coverage_score, active_goal}` → returns `gap_severity` enum + `rationale`
5. Return clusters sorted by severity desc

**Acceptance test:**
- Integration: real corpus + real `portfolio.json` + active goal → returns sorted clusters, top cluster has higher demand × lower coverage than bottom

**Commit:** `BA: find_portfolio_gaps tool (deterministic clustering + LLM severity)`

### Task 7: Project + setup proposers

**What:** Two LLM-backed proposer tools: `propose_project` and `propose_setup_from_corpus`. Both with strict structured output. `propose_setup_from_corpus` runs `backtest_setup` internally and refuses if backtest_count == 0.

**Files:**
- `ai/agents/ba_proposer.py` (extend) — `draft_project_brief`, `draft_setup_proposal`
- `ai/prompts/ba_project_brief.py` (new)
- `ai/prompts/ba_setup_proposal.py` (new)
- `assistant/ba_tools.py` (extend) — `propose_project`, `propose_setup_from_corpus` tools
- `tests/integration/ai/test_ba_proposers.py` (new)

**Logic for `propose_project(theme, window_days=30)`:**
1. `analyze_corpus(window_days, source_pattern=f'%{theme}%')`
2. Read `portfolio.json` via existing `PortfolioStore.list_all()`
3. Read active goal via `GoalStore.get_active()`
4. Single LLM call with `response_format=ProjectGapBrief` — schema rejects WHY-less outputs
5. Return brief as dict

**Logic for `propose_setup_from_corpus(theme, filter_hint=None)`:**
1. `analyze_corpus(window_days=30, source_pattern=f'%{theme}%')`
2. Read portfolio + goal
3. LLM call with `response_format=SetupProposal` — produces `name`, `tier`, `filter_dsl`, `prose`, WHY fields
4. **Run `backtest_setup` with the proposed `filter_dsl`**, embed `backtest_count` in the returned proposal
5. If `backtest_count == 0` → return `{"error": "proposed filter has no corpus matches; widen the theme or run more scans first"}`
6. Return proposal as dict; agent presents conversationally; if operator says yes, agent calls existing `create_setup`

**Acceptance test:**
- Integration: real corpus + portfolio + goal → both tools return well-formed structured output
- Integration: stub LLM to return WHY-less response → tool surfaces validation error to operator
- Integration: `propose_setup_from_corpus` with theme that has no corpus matches → returns error instead of zero-match proposal

**Commit:** `BA: propose_project + propose_setup_from_corpus tools`

1. `uv run pytest tests/unit -q` (sub-second)

3. Smoke: import `assistant.tools.build_tools` and verify no import errors

## Risks specific to execution

- **gpt-5-mini flattening structured output args**: the recent `set_setup_*` refactor showed gpt-5-mini doesn't reliably nest dicts. The BA proposer tools take *theme strings*, not nested filter dicts, so this trap is largely avoided. The one place we might hit it is `search_market(query, filters)` where filters is a dict — if the model flattens, fall back to splitting per-filter wrappers (e.g. `search_market_payment_verified`). Watch for this in early manual testing.
- **Corpus too small at first run**: until BA scans accumulate data, `find_portfolio_gaps` and the proposers will return thin results. Plan: first session after merge, run 5-10 manual `search_market` calls across diverse queries to seed the corpus before hitting the analytical tools.
- **Active goal missing**: agent prompt instructs it to nudge operator to set a goal first. Tools don't crash, just return goal-less analysis with a flag.
